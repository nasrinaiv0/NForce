# P0.3 private workforce and payroll-policy candidate

Parent: PR #4, 0384bfa8372ae5934536f55c65b3987bc2286d72. All existing live payroll write gates remain closed. No hosted migrations, resources, merges or production changes.

## Architecture
- Append-only effective-dated employment eligibility, historical shifts and rest days, explicitly covered historical calendars and versioned policy references. Private authorized import functions audit each write. No inference from current membership; all known memberships require day coverage, including non-eligible dates. An attested external source is still required: ordinary lifecycle/scheduling UI does not populate history yet; a trusted historical importer and completeness review are prerequisites.
- Weekly materializer creates and seals historical roster and day-policy snapshots atomically. Historical changes overlapping a sealed week fail closed. The historical shift records are preserved for review; punches determine elapsed worked time, not scheduled shift duration.
- Reconciliation wraps P0.2 validated punch evidence to classify worked minutes by shift-start local date, rest/holiday class, chronological approved OT and local night window. Versioned multipliers are data, not a legal recommendation. UTC elapsed-minute generation handles local offset transitions; independent DST and policy coverage tests remain required. Candidate is hours and multipliers only, not wage calculation or export.
- Post-lock adjustment proposals and separate decisions are append-only and require distinct authorized actors (neither may be the affected employee). Idempotent proposal retry; negative adjusted code balance rejected; original locked snapshots preserved. Existing codes only; new-code reclassification and currency settlement are not implemented.
- SQL functions remain private and explicitly denied to API roles. No new public endpoints, no frontend activation. P0.2 global write serialization remains intentionally conservative; scale, deadlock and wider write-race tests remain mandatory. The CI runner now invokes two independent PostgreSQL connections against its throwaway local socket to assert a single payroll lock, snapshot and audit entry.
